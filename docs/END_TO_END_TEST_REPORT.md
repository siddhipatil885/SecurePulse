## Safe manual acceptance procedure

1. On the host, open `http://127.0.0.1:5173`. Confirm each camera card changes from `CONNECTING` to `LIVE` and video frames advance. Check `front_door` and `laptop_camera` separately. The current local-only ICE candidate is `127.0.0.1:18556`.
2. Record the UTC start time. Have an authorized person walk through the `front_door` camera's field of view, wait for the event to end, then repeat for `laptop_camera`. Do not use synthetic test-pattern footage.
3. In Frigate at `http://127.0.0.1:15000`, open **Events** and filter each camera and label `person`. For API evidence, query `/api/events?camera=front_door&label=person&after=<unix-seconds>` and repeat with `camera=laptop_camera`; retain the returned Frigate event ID. For each ID verify `/api/events/<id>` has `has_snapshot=true` and `/api/events/<id>/snapshot.jpg` returns 200.
4. Verify the MQTT delivery on topic `frigate/events` with a temporary subscriber authenticated as the backend user. Use the credentials already in the Person 1 deployment environment without printing them. Match the MQTT payload's event ID and camera to the Frigate event. Do not publish to this topic.
5. Confirm backend receipt at `http://127.0.0.1:18000/health/edge`: `last_event_at` advances, MQTT remains connected, and queue rejections/processing failures/invalid events remain zero. Confirm the event via `http://127.0.0.1:18000/api/v1/events?page=1&page_size=10` and match its `frigate_event_id` and camera id.
6. In PostgreSQL, verify the matching row read-only: `docker exec securepulse-person1-postgres-1 psql -U securepulse -d securepulse -c "SELECT id,camera_id,event_type,object_type,timestamp,frigate_event_id FROM security_events ORDER BY timestamp DESC LIMIT 10;"`. Do not modify records.
7. Refresh the dashboard. Confirm the new event appears with the matching camera and time, and that its event count/data updates. Verify video playback independently; a database row alone does not prove WebRTC.
8. Record sanitized timestamps, event IDs, status codes, and results only. Do not include credentials or private imagery.

If no event is generated, inspect Frigate logs/stats and camera framing/lighting, then repeat. Avoid publishing fake event messages into the event topic; that would not validate actual inference. The browser test must be completed in a real host browser; command-line HTTP and snapshot checks do not establish WebRTC playback.
